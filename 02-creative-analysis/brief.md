# Задание: сервис анализа и подготовки креативов (`apc-creatives`)

Документ для команды. Читать вместе с общими требованиями (`common-requirements.md`).

## Кто мы и зачем это нужно

Мы делаем платформу для наружной рекламы: рекламные щиты, цифровые экраны, транспорт. Клиент
выбирает места на карте, оформляет заказ и загружает **креативы** - файлы, которые поедут в печать
или на экран: PDF или TIFF для щита 6 × 3 метра, ролик mp4 на 15 секунд для экрана 1920 × 1080,
картинки, иногда HTML5-креатив архивом для экранов, которые такое принимают.

Сегодня такой файл принимается почти на веру: у видео мы даже не читаем длительность (человек
вводит её руками), просматривающий открывает исходник на 40 МБ, а запрещённое содержание никто
автоматически не ищет. Нам нужен один сервис, который делает всё это за людей и отдаёт им
подсказки. **Решение всегда остаётся за человеком** - сервис проверяет, объясняет и готовит
материалы.

## Задача одной фразой

Сделать сервис, который получает файл (картинку, PDF, видео, HTML-архив) и требования к нему,
а возвращает: честные метаданные, список несоответствий словами, оценку рискованного содержания
с объяснением, превью и перекодированные версии в S3.

## Что должен уметь сервис

**Обязательно**

1. **Приём файла**: загрузка, ссылка, объект в S3. Тип - по содержимому, не по расширению.
   Хэши `sha256` (ключ дедупликации) и `md5`. Видео до 2 ГБ - на диск, не в память.
2. **Метаданные**: картинка (размер с учётом EXIF-поворота, DPI, цветовое пространство RGB/CMYK,
   альфа, анимация), PDF (страницы, размер страницы в мм, растр или вектор, эффективное
   разрешение, шрифты, JavaScript внутри), видео (кодек, профиль, разрешение с учётом поворота,
   fps, длительность в мс, битрейт, битность, HDR, `faststart`, аудио и его громкость, чёрные кадры
   в начале и конце, стоп-кадры), HTML-архив (точка входа, файлы, внешние ссылки).
3. **Проверка против требований**, которые присылает клиент API (см. пример спеки ниже):
   формат, размер файла, пропорции и минимум пикселей на метр для печати, масштаб макета,
   разрешение и ориентация для экрана, длительность не больше слота с допуском, fps, кодек,
   битрейт, аудио запрещено или нет. Ответ - `errors` (блокируют), `warnings` (для проверяющего),
   `info`, каждый с машинным кодом и текстом по-русски.
4. **Производные**: превью JPEG/WebP 320/800/1600 px в sRGB (CMYK и HDR приводятся), постер
   видео (не чёрный кадр), раскадровка 3 × 3, первая страница PDF в PNG, прокси-видео H.264 720p
   до 2 Мбит/с с `faststart`, чтобы играло в браузере.
5. **Перекодирование по профилям** из конфига: `screen-h264-1080p` (типовой для цифровых экранов: H.264 High@4.1, `yuv420p`,
   25/30 fps, ≤ 8 Мбит/с, mp4 `faststart`, AAC или без звука) и `screen-exact` (в точное разрешение
   экрана с политикой `contain`/`cover`/`stretch`). Результат проверяется ffprobe на соответствие профилю.
6. **Модерация содержания**: категории риска (нагота, насилие, оружие, наркотики, экстремистская
   символика, алкоголь, табак, азартные игры, лекарства, финансы, дети, шок-контент), OCR текста на
   русском и английском с правилами (стоп-слова, телефоны, сайты, QR-коды), для видео - по
   выборке кадров с таймкодами. Вердикт `allow | review | block` по настраиваемым порогам и
   объяснение: категория, уверенность, кадр, область. Модели - открытые, работают локально на CPU;
   облачные - только как дополнительный адаптер за портом.
7. **HTML-архивы**: безопасная распаковка с лимитами, проверка структуры и внешних запросов,
   рендер headless-браузером в разрешении экрана → скриншот и отчёт (ошибки, сетевые запросы,
   время первого кадра).
8. **Дубликаты**: точные по `sha256`, похожие по перцептивному хэшу картинок и постеров.
9. **S3**: любое S3-совместимое хранилище (локально MinIO). Производные - в бакет, в ответе ключи
   и подписанные ссылки со сроком.
10. **Задания**: асинхронные с приоритетами и списком задач, статус и прогресс, callback с подписью
    и повторами; **синхронный быстрый путь** `POST /v1/probe` (метаданные + проверка, ≤ 3 с) для
    мгновенного ответа при загрузке. Повтор того же файла с той же спекой не считается заново.
11. **Безопасность разбора**: любой файл считается враждебным. Декомпрессионные бомбы, битые
    заголовки, PDF с JavaScript, SVG со скриптами, zip с выходом из каталога - задание падает с
    понятной ошибкой, сервис продолжает работать, лимиты памяти и времени соблюдены.

**Желательно**

- Демо-страница: загрузить файл и спеку, увидеть всё, что сервис нашёл, превью и прокси; без неё
  приёмка идёт через Swagger UI и коллекцию запросов.
- Читаемость для наружки: слишком мелкий текст относительно холста, слишком много слов, низкий
  контраст, важное у края - как предупреждения.
- Анимированное превью WebP, профиль HEVC, «бесшовный цикл» (первый и последний кадр похожи).
- Адаптер облачной модели модерации за тем же портом.

## Пример спеки (что присылает клиент)

```json
{ "media_class": "digital", "res_w": 1920, "res_h": 1080, "orientation": "landscape",
  "slot_duration_sec": 15, "duration_tolerance_ms": 100, "formats": ["mp4", "jpg", "png"],
  "max_file_mb": 40, "codecs": ["h264"], "max_bitrate_kbps": 12000, "fps": [24, 60], "audio": "forbidden" }
```

```json
{ "media_class": "static", "width_cm": 600, "height_cm": 300, "aspect_tolerance": 0.02,
  "min_px_per_meter": 300, "scale": "1:10", "formats": ["pdf", "tif", "jpg"], "max_file_mb": 40 }
```

## Скорость

Ориентиры, а не экзамен, на 2 ядрах без GPU: метаданные картинки ≤ 1 с, видео
из S3 ≤ 3 с (читать заголовки диапазонами, а не скачивать всё), превью ≤ 2 с, перекодирование
минуты 1080p ≤ 3 минут, модерация картинки ≤ 3 с, ролика на минуту ≤ 60 с.

## Ограничения

- Стек свободный, защищается в design doc.
- Docker, Linux x86_64, профиль «2 vCPU / 4 ГБ / без GPU» обязан работать; GPU - ускорение.
- Файлы клиентов никуда не отправляются без явной настройки; по умолчанию всё локально.
- Внешние утилиты вызываются с аргументами массивом, без сборки командной строки из данных.

## Как принимаем

Коротко и по делу: сервис поднимается на чистой машине одной командой, проходит сквозной сценарий
на наших данных, вы показываете свои замеры и отчёт о качестве, мы читаем код. Подробного
чек-листа заранее не даём намеренно: нам важно хорошее решение, а не решение под проверки.
